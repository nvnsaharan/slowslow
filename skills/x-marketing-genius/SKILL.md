# X Marketing Genius

Write for internet attention, not for sounding like a marketer. Every post needs a reason to stop scrolling — hook → curiosity → payoff → emotion/utility → reply-or-share potential. This governs *how* posts are written; CLAUDE.md §7-10, §33, §36 govern *when* to post and the review/publish gate — follow both, this skill doesn't override the DRAFT → REVIEW → PUBLISH default.

## Before writing

If `twitter-mcp` is connected, check the account's own history first — it beats generic advice:
1. Pull recent posts, find the outliers (high vs average engagement).
2. Look for patterns: hook style, length, topic, humor, personal story vs advice, product-launch framing.
3. Read replies on the best performers if useful.
4. Form a hypothesis ("experiments outperform generic takes") — don't treat one data point as proof.
5. If the MCP isn't connected/authorized, say so explicitly and write from principles below instead of guessing at performance data.

## Finding the angle

Weak ideas usually have a stronger idea hidden inside. Before writing, ask "what's the actually interesting part of this?" and amplify that, not the surface fact.

- Weak: "I built a website with AI."
- Better: "I wanted to see how much of a product I could ship without writing the code myself."
- Best: "I gave AI the whole spec and realized halfway through I didn't understand my own product."

Pick a hook mechanism that fits: curiosity, contrarian, specificity, status, vulnerability, discovery ("I just realized..."), experiment ("I tried X so you don't have to"), challenge, open loop, pattern-recognition, humor, real social proof, before/after. Never invent evidence, numbers, or reactions.

## Archetypes

Observation · Build-in-public · Experiment (hypothesis → what happened) · Founder story (expected X, got Y) · Product launch (story-first, not "I built X! 🚀") · Challenge/participation (with a clear payoff for the participant, not "drop your startup below" with nothing back) · Genuine question · Mini insight · List (only if the list itself is valuable) · Reply.

Product launches specifically: lead with why-should-anyone-care, the problem, the surprising insight behind it — show the product through the story, don't announce it.

## Voice rules

- No CTA ("What do you think?", "Agree?") unless there's a real reason for discussion.
- Ban the generic-guru phrasebook: "Here's the thing," "Unpopular opinion," "Let that sink in," "Nobody is talking about," "10x your X," "Game changer," "Stop doing X. Start doing Y," "Founders need to understand," "AI is going to change everything" — matches CLAUDE.md §7's existing voice ban list, extend it, don't relax it.
- Max 1-2 real hashtags, only if genuinely useful for discovery (per §7) — never decorative.
- No excessive emojis, no LinkedIn-corporate phrasing, no manufactured controversy or fake authority.
- Small imperfections read as more human than a polished sentence — prefer "I tried this" over "I embarked on an exciting journey to explore."
- The first ~280 characters must earn the expand/scroll-stop on their own — never waste it on "Hi everyone" / "I'm excited to announce" / throat-clearing.
- Threads only when one tweet genuinely can't hold the idea — not every thought needs one. Tweet 1 = strongest hook, tweet 2 = context, 3+ = evidence/story, last = takeaway.

## Virality check (before returning any draft)

Would I stop scrolling? Is there a curiosity gap? Is the idea clear? Is the payoff worth it? Does it sound like a real person? Would someone reply, or send this to a friend? Is anything in it unnecessary? Does the account/voice fit? If weak on more than one, rewrite before showing it.

## Output format

When asked for a tweet, return 3 substantively different directions (not minor rewordings):

```
## Recommended
<tweet>

## Alternative — Curiosity
<tweet>

## Alternative — Bold
<tweet>

Why the recommended version is strongest: <1-2 sentences>
```

For "find something to tweet" (per CLAUDE.md §9): scan recent commits/product changes/experiments/feedback, then propose 3 ideas this way, not one.

For a reply: be concise, add something new, don't restate the original tweet, match the thread's tone — a good reply makes the original author want to respond.

## Rules

- Never publish without explicit permission per CLAUDE.md §33 (DRAFT → REVIEW → PUBLISH is the default; "post this" authorizes just that one, "automatically post updates" authorizes the standing behavior).
- Never invent engagement numbers, screenshots, or historical performance if `twitter-mcp` isn't available — say the data isn't accessible rather than estimating it as fact.
- Before publishing, check for accidental secrets/private info per §34, and hold anything uncertain for review per §33.
- Optimize in this order: authenticity > cleverness, specificity > generic advice, interesting ideas > engagement tricks, real evidence > manufactured proof, long-term audience > short-term virality (§10 — track reach/engagement, but don't optimize for followers alone).
